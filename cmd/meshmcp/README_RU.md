# meshbot-meshmcp 🎙️📡

**Говорите с mesh-рацией. В прямом смысле.**

`cmd/meshmcp` подключает голосового ассистента [XiaoZhi](https://xiaozhi.me) к
LoRa-станции MeshCore. Спросите у колонки на столе: *«есть новые сообщения в
mesh?»* — и она их зачитает; скажите *«ответь Wire: уже иду»* — и сообщение
уйдёт в радиоэфир.

Это **самостоятельная фича**: мост сам открывает соединение с устройством
MeshCore (BLE или USB-serial, та же секция `Connection`, что и у всего
meshbot) и больше ни в чём не нуждается — ни в HTTP-шлюзе, ни в боте.

Со стороны XiaoZhi используется протокол **MCP access point**, и весь фокус —
в направлении соединения:

```
[Устройство XiaoZhi] ⇄ ws ⇄ [облако xiaozhi.me] ⇐= исходящий wss =⇐ [cmd/meshmcp]
                                                                        ⇅ BLE/serial
                                                                   [устройство MeshCore]
```

Мост **сам дозванивается** до xiaozhi.me и на этом соединении работает как
MCP-сервер (Model Context Protocol) — облако выступает MCP-клиентом.
Соединение исходящее, поэтому всё работает за NAT провайдера, за CGNAT, за
файрволом: без проброса портов, без белого IP, без туннелей. Тот же механизм
используют XiaoZhi-интеграции вроде nanobot.

## Что умеет ассистент

| Инструмент | Пример голосовой команды | Что делает |
|---|---|---|
| `mesh_get_new_messages` | *«прочитай новые сообщения»* | Зачитывает непрочитанные mesh-сообщения (по 10 за вызов, с долистыванием) |
| `mesh_send_message` | *«отправь Короеду: буду через час»* | Отправляет личное сообщение или сообщение в канал |
| `mesh_search_contacts` | *«найди контакта Йорика»* | Ищет контакты по фрагменту имени (регистр и эмодзи не важны) — так ассистент находит адресатов в большом списке |
| `mesh_list_contacts` | *«кто есть в сети?»* | Перечисляет первые известные имена узлов — для небольших списков |
| `mesh_list_channels` | *«какие каналы есть?»* | Перечисляет настроенные каналы |

Ошибки инструментов возвращаются человекочитаемым текстом («получатель не
найден — проверьте имя через mesh_list_contacts»), так что ассистент объяснит, что
пошло не так, а не промолчит.

## Настройка

**1. Получите URL точки подключения MCP.** Зайдите в
[консоль xiaozhi.me](https://xiaozhi.me) → откройте своего агента (智能体) →
найдите **MCP 设置 / 获取 MCP 接入点** и скопируйте URL точки подключения
(`https://api.xiaozhi.me/mcp/?token=…`). Точка привязана к конкретному агенту:
инструменты появятся у этого агента.

**2. Настройте и запустите:**

```yaml
# config.yaml (тот же файл, что и у всего meshbot)
MCP:
  endpoint_url: "https://api.xiaozhi.me/mcp/?token=XXXX"  # из консоли

Connection:
  type: "bt"             # "bt" (BLE, по умолчанию) или "serial" — как везде
  # serial_port: "/dev/ttyUSB0"
  # serial_baud: 115200

Shrink:                  # как голосовые сообщения подгоняются под эфир
  cyr_to_lat: true       # сжатие кириллицы в визуально идентичную латиницу
  # max_bytes: 140       # жёсткий лимит эфира
  # overrides:
  #   xiaozhi: split     # голос и так делит по умолчанию; можно переопределить
```

```sh
go run ./cmd/meshmcp
```

Индикатор MCP в консоли должен позеленеть через несколько секунд. Дальше
просто разговаривайте с устройством XiaoZhi.

### Параметры конфигурации

| Ключ | По умолчанию | Значение |
|---|---|---|
| `MCP.endpoint_url` | *(обязателен)* | URL точки подключения MCP агента из консоли xiaozhi.me |
| `Connection.*` | как у всех команд | К какой станции MeshCore подключаться и как |
| `Shrink.*` | для голоса — `split` | Подгонка исходящих сообщений — см. «Детали поведения» |

### Одна команда на устройство

Мост подключается к компаньону напрямую. Не запускайте его на **том же
физическом устройстве**, что `cmd/web` или `cmd/bot` одновременно —
MeshCore-компаньон обслуживает одно BLE/serial-соединение. Разные устройства —
пожалуйста. (Нужны и HTTP API, и голос на одной рации? Запускайте по очереди
или поставьте вторую рацию на стол.)

## Детали поведения

- **Отправки подгоняются под эфир.** Исходящие голосовые сообщения проходят
  через тот же модуль shrink, что и все отправки бота. По умолчанию сообщение
  длиннее лимита эфира **делится** на части с маркерами `[i/N]`, которые
  уходят одна за другой (каждая — до ~30 с эфира). С `Shrink.cyr_to_lat: true`
  кириллица сначала сжимается в визуально идентичную латиницу — это экономит
  байты. Стратегию можно переопределить: `Shrink.overrides.xiaozhi`
  (`truncate`, `split`, `llm`, `skip`).
- **Русский находит английские имена.** Ассистент работает по-русски, поэтому
  сопоставление контактов — фонетическое и не зависит от языка: скажите
  *«Йорик»* — и поиск, и отправка найдут `Yorick 💀` (и наоборот: латинское
  написание найдёт `Короед`). Сначала пробуется точное имя, затем игнорируются
  регистр, эмодзи и пунктуация, и лишь потом включается фонетический
  нечёткий поиск с небольшим бюджетом правок. Если подходят несколько
  контактов сразу, ассистент перечислит их и попросит назвать полное имя.
- **Голосовой курсор.** При старте мост сначала синхронизирует сообщения,
  сохранённые на устройстве, и только затем ставит курсор на самый свежий ID —
  поэтому «новые сообщения» значит *пришедшие, пока мост работает*;
  накопленный до старта бэклог вслух не зачитывается. Курсор переживает
  переподключения к xiaozhi.me; перезапустите мост, чтобы начать с чистого
  листа.
- **Медленная отправка — это нормально.** Подтверждение доставки по радио
  занимает до ~30 секунд; `mesh_send_message` ждёт столько, и ассистент
  подтверждает с паузой.
- **504 ≠ потеряно.** Отправка без радиоподтверждения возвращается как
  «передано, но не подтверждено — возможно, ещё дойдёт»; не повторяйте её
  вслепую — ретраи радио могут всё-таки донести.
- **Автопереподключение**, в обе стороны: к xiaozhi.me (экспоненциальная
  задержка, 2 с → 60 с) и к BLE-устройству (периодическая статистика как
  сторожевой таймер). Связь с xiaozhi.me удерживается WebSocket-пингами
  каждые 30 с — паузы между голосовыми командами иначе приводят к обрыву по
  таймауту простоя на NAT или балансировщике (close 1006); канал без понга
  считается умершим через 90 с.

## Карта кода

`cmd/meshmcp/main.go` (корень композиции), `internal/xiaozhi/session.go`
(исходящий WebSocket и переподключение), `internal/xiaozhi/protocol.go`
(JSON-RPC/MCP-протокол + реализация инструментов), `internal/xiaozhi/mesh.go`
(интерфейс `Mesh` + прямой бэкенд к устройству), `internal/xiaozhi/tools.go`
(описания инструментов), `internal/companion` (общий рантайм устройства:
подключение, стартовая синхронизация, инбокс, keepalive).
